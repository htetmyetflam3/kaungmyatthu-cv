# Kaung Myat Thu — Job Application & Portfolio

Multi-page React + Vite site — the portfolio as a job application for Happy Baby One stop baby mart (marketing-led; Digital Marketing Executive primary, Supervisor fallback).

## Pages

Three main pages:

- `index.html` — Resume: CV-style — About (1–2 lines → About), Education, Experience, Freelance, Skills, Services, References. Source of truth for the resume; the static PDF is sent separately.
- `about.html` — personal blog: one post ("About me") — the full story, years inside the body, trauma included, personal-blog region clearly stated. Later: expand to a multi-post index.
- `portfolio.html` — **selected work / marketing application page**: 321 case study (with collapsible *Supporting records*), scripts, writing, CSM, prompt engineering. This page carries the copy employers read, so keep it in step with `case-study.html` / `content.html`.

Detail pages:

- `case-study.html` — 321 Ecolife case study (separate from warehouse)
- `warehouse.html` — NPT warehouse supervisor + CSM car-parts shelf map / POS
- `content.html` — original writing + client-ready scripts
- `myangustis.html` — Myangustis (own development, Burmese text toolchain)
- `ai.html` — AI / prompt-engineering manuscript
- `projects.html` — freelance web-development safety net (Yumeyuki alive / TTS-AE dead / Writermorphosis current app)

Plain-HTML pages (no React entry): `cv.html` (static CV), plus the shared `src/main.js` / `src/styles/main.css` design system and `public/Kaung-Myat-Thu-Portfolio.pdf`.

## Development

```bash
npm install        # install dependencies
npm run dev        # local dev server
npm run build      # production build into dist/
npm run preview    # serve the production build
```

React pages share `src/layout/Layout.jsx` (topbar, footer, viewer dialog, to-top button) and reuse the same design system as the old static pages: `src/styles/main.css` (navy/teal, Myanmar font) plus Bootstrap. Each page is one HTML entry with its own Vite build chunk.

## Static assets — tracked

`cv.html`, `portfolio.html`, `src/main.js`, `src/styles/main.css`, `src/assets/` (Myanmar font, images) and `public/` (portfolio PDF, brand marks, avatar, `.nojekyll`) are all tracked in git, so a fresh clone plus `npm ci && npm run build` reproduces the whole site with no external storage.

## Build output & hosting — GitHub Pages only

`vite build` emits each page as a plain static HTML file with hash-fingerprinted assets into `dist/`. Nothing in `dist/` is committed: the Pages workflow rebuilds it on every push.

- Host: **GitHub Pages** (project site — `https://htetmyetflam3.github.io/kaungmyatthu-cv/`). Vercel is no longer used and there is no `vercel.json`, `api/` folder or server code in the repo.
- Deploy: `.github/workflows/static.yml` — push to `main` (or run it manually from **Actions**). It runs `npm ci`, `npm run build`, uploads `dist/` and deploys it.
- Repo setting required once: **Settings → Pages → Source: GitHub Actions** (already set; `build_type: workflow`).
- All runtime assets are tracked in git: `public/` (portfolio PDF, brand marks, avatar, `.nojekyll`) and `src/assets/` (Myanmar font, images). `base: './'` in `vite.config.js` keeps every link relative, so the site works from the `/kaungmyatthu-cv/` sub-path.
- `public/.nojekyll` is copied into `dist/` so Pages serves the build untouched (no Jekyll pass).

**No Express server and no SPA fallback are needed.** This is a static multi-page site: each `*.html` file (index, portfolio, cv, case-study, content, …) is a real file with real content, so a plain request to `/case-study.html` resolves on its own. An SPA `404.html`/rewrite trick is only needed when the app has one HTML shell and client-side routes; there are none here.

## Content rules worth keeping

- 321 follower figures: the confirmed month-end series is the headline (`157,000 → 187,375 → 298,104`, Oct → Dec, +90%). December's month-end increase is **110,729**; the surviving daily entries total **56,591** and do not reconcile with it. The two are presented as separate records — the daily series is explicitly *not* a breakdown of monthly growth, and it lives in the collapsible **Supporting records** block (`portfolio.html`, `src/pages/CaseStudy.jsx`).
- Writing samples are credited as **selected translation, adaptation & original writing** — not as authored source material.
- Keep `cv.html`, the React pages and `public/Kaung-Myat-Thu-Portfolio.pdf` in step; rebuild the PDF after copy changes.

## Single portfolio PDF

`public/Kaung-Myat-Thu-Portfolio.pdf` is generated by `tools/build_pdf.py` (not a browser print-to-PDF) and is committed, so the download link works on Pages. The PDF copy must match the site copy. Rebuild it after any portfolio/copy change:

```bash
python3 -m venv .venv-pdf && . .venv-pdf/bin/activate
pip install fpdf2 beautifulsoup4
python3 tools/build_pdf.py public/Kaung-Myat-Thu-Portfolio.pdf
# 13 pages expected; check the session fixtures in tools/samples.json if it fails
```

`tools/build_samples_pdf.py` builds the separate three-sample PDF (linked from Google Drive) from `tools/samples.json`.
